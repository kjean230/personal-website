- **Database (S2)** — schema is brief §4 verbatim; access rules are brief §7. Conventions:
  - Migrations are `supabase/migrations/<YYYYMMDDHHmmss>_<name>.sql`, applied in filename order. A migration that has reached `main` is never edited — add a new file. `lane/spine` was that boundary while the spine was the only lane; from here it is `main`, plus any live `lane/*` a sub-branch has already built on. The reason is not style: once a migration reaches `main` the Supabase GitHub integration has applied it to the hosted project and recorded it in `supabase_migrations.schema_migrations`, so editing the file leaves the repo and the hosted database disagreeing about what ran, with nothing to detect the difference. Every object gets **explicit** `revoke`/`grant`s (the hosted default no longer exposes new `public` objects to the Data API roles; the local image still does) and RLS is enabled on every table.
  - Access model: `anon` reads all content tables; on `reactions` it may `insert (entry_id, emoji, ip_hash)` only and reads aggregates through the `reaction_counts` view — never raw rows. Writes require `public.is_admin()`, which is true only when the JWT carries `app_metadata.role = 'admin'` (set by the service role / dashboard, never by the user). `service_role` bypasses RLS. Emoji allowlist and the 64-hex `ip_hash` shape are CHECK constraints, so they hold for every writer.
  - `entries.kind` and `entries.facet` are deliberately not enumerated in the database (new section types cost zero migrations); Zod schemas keyed on `kind` (S4) own their values. `status`, `relation_type`, `tags.category`, `links.kind` are closed sets enforced by named CHECKs. Relations read `<from> <relation_type> <to>` (project `part_of` experience, certification `certifies` experience).
  - `supabase/seed.sql` is **fixture data only** (`metadata.fixture = true`), proving the brief §4.1 shape. `supabase/seed.content.sql` is the **real content** (S3): generated once from the LinkedIn export, then owner-edited; every row has a fixed id (never change one), `metadata.source`, and `metadata.date_precision` (LinkedIn gives months, so the day is `01`); relations are written by slug and fail the seed loudly if a slug is missing; `-- REVIEW` marks a field the export could not supply or a judgment to confirm. Both seeds run locally and in CI in that order (`SEED_FILES` in `apply.mjs` = `[db.seed] sql_paths` in `config.toml`), never on production. Honors are `kind = certification` with `metadata.category = "award"` (the trophy case holds both — brief §5).
  - `supabase/tests/rls.test.ts` is the executable statement of the §7 rules — extend it whenever a policy or grant changes; keep its counts fixture-filtered, since real rows load after the fixture. `supabase/tests/content.test.ts` pins the real BTT record's three placements and the content seed's idempotency. `DATABASE_URL` is local-only; hosted credentials go in Vercel/Actions secret stores and never in the repo.
  - **Query layer (S4)** — the app reads only through `lib/content/queries.ts` (`listSection`, `getFacetCounts`, `listRelated`, `getEntryBySlug`, `listTrophies`; contract in `handoff/feat-spine-api.md`), which reads via supabase-js over PostgREST as `anon` with the two public `NEXT_PUBLIC_SUPABASE_*` values — never a database connection string in app code. `lib/content/schema.ts` is the **single source of the `kind` / `facet` value sets** (brief §4) and of each kind's metadata keys; a row that fails it throws (`ContentValidationError`) rather than disappearing. Every list requests `count: "exact"` and throws if PostgREST truncated it at `max_rows`. Caching is the fetch Data Cache (`next: { revalidate: 3600, tags: ["content", "content:<table>"] }` added in `lib/db/client.ts`), revalidated through `lib/content/revalidate.ts`; a route that reads at prerender inherits that window unless it declares its own — no `cacheComponents`, no `'use cache'`. `supabase/tests/api.test.ts` exercises the layer end to end against the sidecar; extend it when a query shape changes.
  - **Route table (S5)** — `lib/routes/table.ts` is the URL contract (its header comment is the table; handoff in `handoff/feat-spine-routes.md`): `SECTIONS` in brief §4.3 order (`/experience` · `/projects` · `/certifications` = the trophy case · `/education` · `/hobbies` = kinds `hobby` + `interest` · `/now` = kind `post`), an entry's canonical URL is `/<section of its kind>/<slug>` (`entryHref`; `sectionForKind` is total over `KINDS` and checked at import), facet chips are `?facet=<facet>` (`parseFacetParam`; invalid → 404), `/resume` is linked from the site header on every page, `/all` is the "All Software" index with `?q=<words>` as its search (`parseSearchParam`; a repeated or over-long `q` → 404 — see Tile grid below), `/privacy` and `/admin` are reserved constants with no page. Adding a section is one `SECTIONS` entry, zero new route files. `lib/routes/load.ts` is what each URL reads (`loadSection`, `loadEntry`, `loadTrophies`, and S6's `loadResume`) through an injectable `queries` object typed against `lib/content/queries.ts`; loaders return discriminated results (`found` / `redirect` / `not-found`) and never import `next/navigation` — only page files call `notFound()` / `permanentRedirect()`, at the top level of the page, outside any `try`. One page file per URL (`app/[section]/page.tsx`, `app/[section]/[slug]/page.tsx`); a slug reached under the wrong section 308s to its canonical URL. Rendering modes: `/[section]` and `/all` read `searchParams`, so they render per request (the fetch Data Cache still bounds database reads to hourly); `/[section]/[slug]` declares `generateStaticParams → []` and is SSG-on-demand under the inherited 3600 s window and `content` tags; `/` is static. **Since S6, `/resume` reads content, so it prerenders at build under the same 3600 s window (`○` with a `1h` revalidate column) and `next build` therefore needs the two `NEXT_PUBLIC_SUPABASE_*` values** — a fresh clone without them cannot build, and a hosted-project outage fails the build rather than a request — **but only with a cold fetch cache**, measured on `chore/spine-loose-ends`: with `.next/cache/fetch-cache` warm, `/resume`'s reads never reach the network and the same outage builds clean, so a deploy surviving an outage proves the cache was warm, not that the project was up. `lighthouserc.json` audits `/`, `/experience`, `/experience/break-through-tech`, `/certifications`, `/resume` and, since `chore/shell-tile-grid-contract`, `/all`.
  - **Recruiter render (S6)** — handoff in `handoff/feat-spine-recruiter.md`. Every page is server-rendered semantic HTML and works with JavaScript disabled, which is a spine acceptance item, not a nicety. (Until S7 that was enforced by there being no `"use client"` in the repo at all; S7 added two islands and the property is now held by *what* they do — see Console shell below — and proved by the script-stripping render, not by a grep.) `lib/render/markdown.ts` is the **only** thing allowed to produce raw HTML — `renderMarkdown(body)` escapes every embedded tag, allowlists hrefs to `http(s)` and site-relative (a bare leading `//` is rejected as off-site), drops non-`http(s)` images, and re-levels headings so the body's shallowest is an `h2` under the page's one `h1`. It is server-only; importing it from a client component would ship `marked` to the browser. **One named exception since `feat/recruiter-seo`:** `lib/render/json-ld.ts` produces the body of every `<script type="application/ld+json">`, rendered only by `app/json-ld.tsx` — a second raw-output point, bent deliberately rather than left looking violated. Its whole boundary is `serializeJsonLd`: `JSON.stringify` of a built object with every `<` replaced by `\u003c` (a global replace), so no `</script` or `<!--` can close the element. JSON-LD is never hand-written. **A second named exception since `feat/shell-boot-profile`:** `MODE_SCRIPT` and `BOOT_SCRIPT` in `app/(explorer)/boot.ts`, the repo's only *executable* inline scripts — constants assembled from that file's own literals, never from request data or content, and `boot.test.ts` fails if either gains a `<`. Every date goes through `lib/render/dates.ts`, which uses **no `Date` objects** and honours `metadata.date_precision` — a month-precision row renders "May 2026" and `<time datetime="2026-05">`, never the seed's placeholder day. `/resume` was entries only through the spine; `feat/recruiter-resume-print` added the contact block, and `app/resume/contact.tsx` is now the **only** file in the tree carrying contact details — see Print below. No media markup ships until a Storage bucket exists (`feat/admin-media`).
  - **Console shell (S7)** — handoff in `handoff/feat-spine-console-tile.md`. `app/(explorer)/` is the shell's **component directory, not a route tree**: it holds no `page.tsx` and no `layout.tsx`, because two route groups resolving to one path is a build error and the architecture fixes one page file per URL. The tile row is the *enhanced rendering of the home page's existing section nav* — the same `<ul>` of `<a>`s, in `SECTIONS` order — so there is no mode switch and no second markup tree; mode is not a URL dimension. Tiles carry no counts, which is what keeps `/` a `○` static route that reads no content; a section with no entries keeps its tile and shows its own empty state on `/<section>`, rather than being hidden and made unreachable. Conventions:
    - **Three client islands, all tiny, all focus/keys only:** `tile-row.tsx` (roving `tabindex`), `back-key.tsx` (Escape) and, since `feat/shell-boot-profile`, `boot-profile.tsx` (the boot dialog — see Boot and profile select below). They receive **server-rendered children**, never content props, so no label, href or SVG reaches the browser bundle. An island must not import `lib/content/*`, `lib/render/*`, `lib/db/*` or `zod` (they would ship `marked`/`zod` to the client), and must not call `useSearchParams()` (it would cost `/` its `○`). Every pure key rule lives in `keys.ts`, which imports nothing — that is the only part testable under Vitest's `node` environment.
    - **The roving `tabindex` is applied after hydration, never in the markup.** The server sends six ordinary links, so JS-off leaves six working tab stops; the island then demotes all but one. Its effect deliberately has **no dependency array** so a soft navigation that replaces the anchors cannot silently restore six tab stops.
    - **Enter is never handled in JS** — the tiles are real `<a>`s and already activate on Enter (brief §2.2's "Enter = A"). A modified arrow (`Alt`/`Cmd`+Arrow is browser back) is never consumed; `nextIndex` returns `null` for it.
    - **Icons are inlined from `design/assets/icons/` by `(explorer)/tiles.ts`**, which ports `design/tokens/build.mjs`'s `inline()`: strip `id` / `role` / `aria-labelledby` **and the `<title>`**, add `aria-hidden="true"`. Stripping is load-bearing — the source files carry hard-coded ids, and a retained `<title>` would give each tile link a second accessible name. The label must stay a **sibling** of the icon span, never inside it. `now` is drawn by `tile-news.svg` (brief §4.3's "Now/News").
    - **`next.config.ts` names `design/assets/icons/**` in `outputFileTracingIncludes`** for `/[section]`, `/[section]/[slug]` and, since `feat/shell-tile-grid`, `/all`. Those routes read the icons at cold start inside the serverless function, and nothing local can reveal a tracing gap because `next start` and Lighthouse both run from the repo root. Any new per-request route that inlines an asset needs the same entry.
  - **Trophy case (S8)** — handoff in `handoff/feat-spine-trophy.md`. `/certifications` (`trophyCase: true`) is the S6 index row **plus a state**, not a second rendering: `app/(explorer)/trophy.tsx` owns the mapping and `app/[section]/page.tsx` keys one branch on `section.trophyCase`. Conventions:
    - **`archived` renders as "Archived", never "Locked"** — three statuses, three states, three drawings, one to one (`TROPHY_LABELS`). An archived credential is one you earned that lapsed, not one you never achieved. **`supabase/seed.sql`'s fixture comment is stale on this point**; this bullet and `trophy.test.tsx` are the authority. `TROPHY_LABELS` is `Readonly<Record<Status, string>>`, so a fourth `status` fails `typecheck` here until someone decides what it looks like.
    - **State is always text.** `<TrophyState>` renders a `<span>` (it nests inside the meta line's `<p>`; a `<p>` in a `<p>` is invalid) whose label is a **sibling text node** of the `aria-hidden` glyph — never colour or icon alone (WCAG 1.4.1, brief §2.2). `TROPHY_ICONS` in `(explorer)/tiles.ts` is keyed by `status`; `archived` is drawn by `trophy-locked.svg`, the same file-vs-meaning mismatch as `now` → `tile-news.svg`. `trophy-unlocked.svg` carries the set's only literal colour, in the sanctioned `var(--color-primary, #E8B11B)` form, inside the path's own stroke — DESIGN.md's outline rule met by the drawing, not a wrapper.
    - **Adding a class to `explorer.module.css` costs client bytes.** `tile-row.tsx` is a client island and imports that stylesheet, so its CSS-module class-name map ships in the browser bundle (S8's two classes = its whole +15 B script delta). The drawings never ship.
  - **Error boundaries (`chore/spine-loose-ends`)** — `app/error.tsx` and `app/not-found.tsx`, closing BUILD_PLAN §7 box 18; handoff in `handoff/chore-spine-loose-ends.md`. The query layer throws and nothing catches (zero `catch` around a content read anywhere in `lib/` or `app/`, deliberately — a swallowed `ContentQueryError` would render an empty section indistinguishable from a section with no entries), so these two are where a failure surfaces. The only `catch` in either tree outside tests is the storage guard in `app/(explorer)/boot.ts` and its two inline scripts, which is the opposite case: blocked `sessionStorage` is an expected state with a correct answer (no boot, Recruiter), not a failure to surface. Conventions:
    - **`app/error.tsx` is a client component** (Next's requirement), so its imports are a client bundle: never `lib/content/*`, `lib/render/*`, `lib/db/*` or `zod`, and therefore its two hrefs are **literals** rather than route-table imports — `lib/routes/table.ts` reaches `zod` through `lib/content/schema.ts`. `error.test.tsx` pins the literals against `HOME_HREF` / `RESUME_HREF` and asserts the import list, because nothing in lint or typecheck notices a client bundle growing. It costs **+1,227 B** of script on every route (the chunk plus `site.module.css`'s class-name map), measured against a same-commit baseline.
    - **Neither boundary mounts a shell island.** `<KeyHints>` brings `<BackKey>` and `useRouter` with it; a page reached because something failed does not add a binding that depends on the machinery under suspicion, and a URL that resolved to nothing has no "up one level" for Escape.
    - **What they do not cover, measured rather than assumed.** Next 16.3.3 serves *both* a 404 and a thrown-render 500 as an empty `<html id="__next_error__">` shell with the content only in the flight payload — so with JavaScript off the body is blank. **This predates the boundaries** (the built-in 404 does the same; verified by rebuilding without these files) and is not something a boundary can change. With JS on both render correctly inside the layout. `/[section]/[slug]` is worse still: it is SSG-on-demand, so a failed first render returns a bare `Internal Server Error` and **never reaches `error.tsx` at all**. Static routes are unaffected — under a full outage `/` and `/resume` serve last-known-good at 200.
    - **`app/not-found.tsx` is a server component** and reads the six sections from `SECTIONS`, so adding a section stays one `SECTIONS` entry (S5's rule) and the 404 costs no client bytes and no content read — `/_not-found` stays `○`.
  - **Print (`feat/recruiter-resume-print`)** — the repo's first `@media print` rules; handoff in `handoff/feat-recruiter-resume-print.md`. `/resume` is the only page with a contact block, and printing is the only thing that reads these rules, so **nothing in lint, typecheck, tests, `tokens:check` or Lighthouse can see a regression here** — emulate print media instead. Conventions:
    - **The print colour pin lives in `app/app.css`, never in `tokens.css`.** `design/tokens/build.mjs` enumerates the four blocks `tokens.css` may contain and fails on a fifth, so a `@media print` block there breaks `tokens:check`. The reason it is needed at all: a print stylesheet **inherits `prefers-color-scheme`**, so without the pin a dark-mode visitor prints `--color-text: #F2ECDD` — near-white — onto a sheet whose background the printer omits, and gets a blank page. The pin restates the themed colours as the static ink tokens under three selectors (`:root`, `:root:not([data-theme="light"])`, `:root[data-theme="dark"]`) that mirror `tokens.css`'s three theme blocks and win on source order.
    - **A print value that is not a token goes into `tokens.css` as a *static* token, not into the print block.** That is why `--color-ink-muted` exists: it is the single source for the light `--color-text-muted`, which now reads `var(--color-ink-muted)`. There is deliberately **no `@page` rule** — custom properties do not resolve in the page context, so a tokenised `@page { margin }` is impossible and a hardcoded one is forbidden; the UA's page margins are used.
    - **`app/resume/contact.tsx` is the only file in the tree carrying contact details.** Its four values are settled in BUILD_PLAN §8 and are exhaustive — no phone, no street address, no personal-site URL. Link text is the value verbatim, which is what lets the printed sheet stand alone without generated content; entry-row links are the opposite case and have their URLs expanded with `attr(href)`, scoped to `.resumeRow .linkList .chip::after` so the contact block is not doubled.
    - **Adding a class to `site.module.css` costs client bytes** — the same S8 finding `explorer.module.css` records, paid here because `app/error.tsx` imports this stylesheet. `.contact` is the sub-branch's one new class name; measured cost **+39 B** of inline payload on every route.
    - **The leak grep is prose, not code.** `PROHIBITED_TERMS` in `build.mjs` is the IP guard (SVGs, `tokens.css`, the chime files) and has never carried PII markers. The contact-leak check is by hand, over added lines of `git diff --cached`, with `app/resume/` excluded; the `@fordham.edu` marker stays anchored, because bare `fordham` hits 35 legitimate org names in `supabase/seed.content.sql`.
  - **SEO (`feat/recruiter-seo`)** — handoff in `handoff/feat-recruiter-seo.md`. Lighthouse's SEO category scored 1.00 before any of this existed and audits only the tags a page has, so **nothing in CI can see a regression here**; the proof is a direct check of the built HTML (the handoff records its shape). Conventions, each measured against Next 16.3.3's own resolver:
    - **`metadataBase` is `SITE_URL`, set once in `app/layout.tsx`; every canonical is a route-table path** (`HOME_HREF`, `RESUME_HREF`, `sectionHref(section)`, the loader's entry `href`) that Next makes absolute. **Canonical is never set in the layout** — metadata merges shallowly, so the 404 page and every page without its own value would inherit it. Each page states its own, and only when it renders: an unknown section, an invalid `?facet=` and a missing slug get none.
    - **A `?facet=` view canonicalises to its bare section** and is never in the sitemap: it is a subset of the section's list, not a page of its own.
    - **No page may set `openGraph`.** A page-level `openGraph` object replaces the layout's wholesale and silently drops the image from `app/opengraph-image.tsx`, which Next merges only at the segment holding the file. `og:title`/`og:description` come from each page's title and the layout's description, and Next fills the twitter card (`summary_large_image`) from the OG image — no `twitter-image` route. `og:url` is deliberately absent for the same reason; `rel=canonical` carries canonicalisation.
    - **`/sitemap.xml` and `/robots.txt` come from the route table** (`loadSitemap` in `lib/routes/load.ts`), so adding a section stays one `SECTIONS` entry. `/privacy` and `/admin` are in neither, and robots.txt has no `Disallow` — robots.txt is not access control, and naming `/admin` would advertise it. `lastModified` is written only for entries, from `updated_at`; no priority or change frequency is invented.

    - **The contract.** The first load of `/` in a session shows the boot, then the profile select; every other URL is the plain recruiter page and never boots. "Session" is one browser tab: `sessionStorage` keys `kj.booted` and `kj.mode`, no cookie, no URL parameter, nothing a server sees — which is what keeps `/` `○`. ## Architecture (as specified)

**Two renderers, one dataset, same URLs.**
- *Recruiter mode* — SSR, semantic HTML, works with JS disabled, canonical for SEO, default for `/`. A plain `/resume` route is reachable in one action from anywhere.
- *Explorer mode* — handheld-console shell (tile row, D-pad/keyboard/gamepad navigation, trophy case, play-activity charts, toasts). An enhancement over the working site, never the only way in.
- Both bind to the **shared route table** (spine S5, `lib/routes/table.ts`), written before either renderer existed. Every tile resolves to a real, shareable URL; no state-only navigation. Mode is not a URL dimension: the same URL serves both renderers through **one App Router page file per URL** (two route groups resolving to one path is a build error), which is the seam the renderers plug into.
- Ownership: the shell lives in `app/(explorer)`, admin in `app/admin`. Shared-component changes are raised before editing.

**Polymorphic `entries` table** (`kind` × `facet`) is the core; new section types must cost zero migrations. Zod schemas keyed on `kind` recover type safety at the app layer. `entry_relations` (`part_of` / `certifies` / `produced_by` / `related_to`) give multi-placement: the Break Through Tech AI worked example (brief §4.1) is one `experience` record that surfaces in Experience, Projects, and the trophy case with zero duplication — every consumer of the data must handle this. `status` (`unlocked` / `in_progress` / `archived`) drives trophy states. Facet-chip counts come from the query, never hardcoded.

**Ingestion is scheduled, not live-proxied.** GitHub Actions cron workers (Spotify, Steam, IGDB) normalize into Postgres; the site only ever reads its own DB and serves last-known-good on upstream failure. Workers are idempotent upserts with retry/backoff and structured logging, and fail loudly as Actions failures. The LinkedIn import is a one-shot pre-spine importer (S3), not a scheduled worker — there is no LinkedIn API, and scraping is off the table.

**Auth is admin-only** (Supabase Auth, one user, guards `/admin`). **Reactions are anonymous emoji only:** fixed server-side allowlist, salted `ip_hash` (never raw IP), edge rate limit, RLS allowing anon `insert` + aggregate `select` only.

**Stack** (decided, brief §3): Next.js App Router + TypeScript · Vercel Hobby · Supabase Postgres / Auth / Storage · GitHub Actions cron (not Vercel Cron) · Zod at every boundary · cookie-free analytics. Cost target $0 + domain. Never commit binaries; tile art and screenshots go to Supabase Storage. No third-party code under a licence incompatible with MIT enters the tree; skills and plugins are installed, never vendored, and their source-available files (`anthropics/skills`' `docx`, `pdf`, `pptx`, `xlsx`) are the named case.

## Non-negotiable constraints

- **IP (brief §2.1):** borrow interaction grammar only. No Nintendo / Disney / Capcom / Square Enix assets, no Joy-Con silhouettes or red/blue pairing, no Switch wordmark, chime, or typefaces, no rendered console hardware, and the phrase "Nintendo Switch" nowhere in UI copy, metadata, filenames, or alt text. Original wordmark, palette (not red/blue), hand-drawn SVG icons, original chime. `DESIGN.md` must record the borrowed-grammar vs. protected-expression distinction.
- **Accessibility (brief §2.2):** full keyboard operation (arrows navigate, Enter = A, Escape = B, roving `tabindex`, visible focus ring, no traps), semantic HTML beneath the shell, `prefers-reduced-motion` disables boot / zoom / parallax, sound off by default, WCAG 2.2 AA in both themes, touch targets ≥44px.
- **Privacy (brief §2.3):** no visitor accounts, no email collection, no fingerprinting, no session replay, no IP-to-company enrichment. Ship `/privacy`.

## Workflow

**Branching (plan §2):** `main` is protected. `lane/<name>` is long-lived, one per lane, rebased on `main` after every `main` merge. `feat/<lane>-<slice>` is a stacked sub-branch that merges into its lane. Sub-branch → lane auto-merges on green CI with no human step (Phase 0 predates CI and merges by hand — plan §3); lane → `main` needs green CI **and** the owner-signed acceptance checklist (plan §7, including its security and IP blocks) — that is the only human merge gate. One agent per lane; never two agents on one lane branch. Every PR body links the lane checklist.

**Commit attribution (owner-only):** every commit is the owner's own work product. Author **and** committer must be the identity in `git config user.name` / `user.email` — the one exception being a squash merge, whose committer is GitHub's own web-flow identity. No `Co-Authored-By` trailer naming an assistant, no "Generated with" footer, and no assistant, model or vendor credited as author, co-author or generator in a commit message, PR title or PR body. This is a rule about *attribution*, not a banned-substring list: naming the file `CLAUDE.md` in a subject line is fine. Verify after every commit — `git log -1 --format=%B`, `git log -1 --format='%(trailers)'` (**must be empty**; the trailer check is the one that actually catches a slip, since a trailer does not appear in a casual read of the subject), and `git log -1 --format='%an <%ae> | %cn <%ce>'`. This repo has no hook, no `commit.template` and no `commit.gpgsign`, so a trailer can only come from the message you write.

**Stopping:** stop when the PR opens — see `BUILD_PLAN.md` §2.1, which is canonical for stopping behavior and is not summarized here.

**Phase order (plan §3–6):** Phase 0 identity (0a proposes three complete identities → **hard stop for the owner's pick** → 0b tokens, icons, wordmark, chime, `DESIGN.md`) → Phase S spine (S1–S8, serial, on `lane/spine`) → Phase 1 lanes, two concurrent maximum and file-disjoint, **ordered by the dependency edges in plan §5.1, not by pair**: `lane/recruiter` has merged; the LCP diagnostic (plan §5.2 — measurement only, never a fix) must be on `main` before `lane/console-shell` is cut; `lane/ingestion` waits for neither; only `feat/shell-play-activity` waits on ingestion; `lane/admin` starts after `lane/ingestion` merges; reactions + content follow → Phase 3 hardening. Nothing visual starts until 0b merges.

**Verify at build time, not from memory (plan §9):** Vercel Hobby non-commercial terms, Supabase free-tier pause behavior and the nightly keep-warm assumption, Spotify / Steam / IGDB API access terms, IGDB cover-art usage rights.
