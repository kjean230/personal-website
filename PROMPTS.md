
# Cowork Session Prompts

`BUILD_BRIEF.md` and `BUILD_PLAN.md` are committed to the repo, and the repo copy is authoritative. Never paste them into a chat — agents read them from the repo. Each Cowork session gets one prompt from this file.

One session per sub-branch. One agent per lane branch. Never two agents on the same lane branch.

---

## Template

Keep the scaffolding character-for-character stable across sessions; vary only the bracketed fields.

```
Context: read CLAUDE.md, BUILD_BRIEF.md, and BUILD_PLAN.md in the repo before
doing anything. The repo copy of each is authoritative.

Precedence: the brief governs scope and constraints. The plan governs order,
branching, and gates. CLAUDE.md governs repo conventions only — commands, code
style, file layout. Where brief §8 and the plan disagree, the plan wins. Where
CLAUDE.md contradicts either on scope or sequencing, the brief and plan win, and
you flag the contradiction instead of silently picking one.

Task: [sub-branch id + name, from BUILD_PLAN §3–5]

Branch: create [feat/branch-name] from [parent lane branch].

Scope: [the sub-branch's row contents, verbatim from the plan]

Out of scope: adjacent sub-branches, refactors outside the touched files,
reopening settled decisions, inventing content of any kind.

Done when: the scope above is implemented, green CI passes, and the preview
deploy is live.

Then: open a PR into [parent lane branch] with the BUILD_PLAN §7 security block
ticked. Write handoff/[feat-branch-name].md and commit it in the same PR, using
the handoff format in the Stop rule section below. Then stop and report. Do not begin
the next sub-branch. Do not continue after the PR is open even if there is
obvious remaining work — name it in the handoff instead.

Tripwire: if this sub-branch turns out materially larger than its BUILD_PLAN
row describes, stop immediately, do not push through. Report what the row missed
and propose a split into two sub-branches. Scope discovered mid-flight is
reported, never absorbed.

Blockers: ask. Do not invent content, names, dates, or assets.
```

## Stop rule

One sub-branch, one session, one PR: the session ends when the PR opens, not when
the work feels finished. `BUILD_PLAN.md` §2.1 is canonical for stopping behavior —
including the early-stop triggers and the auto-merge mechanics — and is not
restated here.

**Every sub-branch commits `handoff/<feat-branch-name>.md`:**

```markdown
# Handoff — <feat-branch-name>

**Merged into:** <lane branch>
**Plan row:** BUILD_PLAN §<n>, <sub-branch id>

## Shipped
- <what actually landed, one line each>

## Deviated from plan
- <anything done differently than the plan row, and why. "None" if none.>

## Deferred
- <work that belongs to this scope but was not done, and where it should go>

## Open questions for owner
- <blockers, decisions needed. "None" if none.>

## Next
<the next sub-branch id per BUILD_PLAN ordering>
```

**Between sessions:** `/clear` before starting the next sub-branch. The handoff
file is the carry-over; the conversation is not. A session that resumes warm
re-reads the entire prior sub-branch on every turn, which is where cost actually
accumulates.

**Resuming after a stop:** paste a fresh template block for the next sub-branch
and point it at the prior handoff file by path. Do not paste the prior handoff's
contents — the agent reads it from the repo.

---

## Ordering

Sessions run in plan order: 0a → 0b → S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8, then lanes two at a time per §5. The spine is serial — do not parallelize S1 through S8, since each depends on the one before.
