## Deviated from plan

- **`metadata.location` renders once, in the dates line only** — the block named `location` both in the dates line and in the `<dl>` of typed keys, which would have printed it twice on one page. The owner chose the dates line; the `<dl>` carries `cause` / `activities` / `credential_id` only and disappears entirely when an entry has none of them. This is the "the `<dl>` keys — strike if unwanted" open question, half-answered.
- **`safeHref` rejects a bare leading `//`.** The block says site-relative hrefs "start with `/`", but `//host/path` is protocol-relative and leaves the site. Strictly safer than the literal reading; tested.
- **`ResumeSection` carries an `id` beside `label`** (`experience` / `projects` / `education` / `certifications`), which the block's sketched shape did not name. It is the `aria-labelledby` target, and generating it in the loader beats slugifying a label inside JSX.
- **One new file the block's file list did not name: `app/entry-dates.tsx`.** Three pages render a date range; the alternative was triplicating the `<time>` markup and letting them drift. It is a server component, not a route file (only `page.tsx` / `layout.tsx` are routes), and it adds no route.
- **Both optional items were taken** on the owner's instruction: the skip link and the extra Lighthouse URL.
- **Local smoke ran on port 3001, not 3000.** A `next dev` the session did not start held 3000 throughout and was deliberately left running; the production build was served on 3001 instead and Lighthouse pointed at the same build there. CI's own config is untouched and still audits `localhost:3000`.
