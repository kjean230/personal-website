## Deviated from plan

- **#28 and #29 are still open, blocked on a token scope, not on their checks.** Both are green. `gh pr merge --squash --admin` fails on each with `refusing to allow an OAuth App to create or update workflow .github/workflows/ci.yml without workflow scope`; the session's `gh` token carries `admin:public_key, gist, read:org, repo` and not `workflow`. Retried once to rule out a transient. **#27 touches the same file and merged**, which makes the rule's behaviour look inconsistent rather than absolute — recorded as observed, not explained. Unblocking it is one interactive command the owner runs: `gh auth refresh -h github.com -s workflow`, or merge the two on github.com. Doing it before `lane/recruiter` opens still avoids rebasing an in-flight lane.
- **A claim in `CLAUDE.md` and two handoffs turned out to be conditional, and was corrected rather than repeated.** "A hosted-project outage fails `next build` rather than a request" is true **only with a cold fetch cache**. Measured both ways: with `.next/cache/fetch-cache` cleared the faulted build exits **1** (`Export encountered an error on /resume/page`); with the cache warm the same faulted build exits **0** and produces a normal route table, because `/resume`'s reads never reach the network. So a deploy surviving an outage proves the cache was warm, not that the project was up. The Route table bullet now says so.
- **`app/error.tsx` uses `<Link>`, not plain `<a>`.** It was written with anchors on the theory that a full document request recovers better than a soft navigation reusing the router state that just failed. `@next/next/no-html-link-for-pages` rejected it, and the theory does not survive inspection: `<Link>` renders the identical `<a href>` in the served HTML, so the JavaScript-off path is byte-for-byte the same. Switched, and the comment now says what is actually true.
