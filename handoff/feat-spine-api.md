### The contract S5, S6, S7 and S8 can rely on (`lib/content/queries.ts`)
Every function takes an optional trailing `client` (defaults to `getAnonClient()`), throws `ContentQueryError` on a Data API error and `ContentValidationError` on an invalid row, and returns validated, plain, cache-serialisable objects.
- `listSection(kind, { facet? }) → EntrySummary[]` — the tile row for one brief §4.3 section, ordered `featured desc, sort_weight desc, start_date desc nulls last, title, slug` (the `entries_recency_idx` order); `facet` omitted = every row, `null` = unfaceted rows only, a facet = that facet. No `body`.
- `getFacetCounts(kind) → { all, byFacet: Record<Facet, number>, unfaceted }` — live chip counts from one request (`all` includes the null facet; every facet present, 0 when empty). Counted in code: PostgREST aggregates are off by default on hosted.
- `listRelated(id) → { outgoing: RelationEdge[], incoming: RelationEdge[] }` — every edge touching an entry, each `{ type, entry: EntrySummary }`, sorted by type then recency. Read `<this> <type> <entry>` for outgoing (a project `part_of` its program) and `<entry> <type> <this>` for incoming (the projects that are `part_of` this).
- `getEntryBySlug(slug) → EntryDetail | null` — `{ entry (with body), links, media (by sort), tags, relations }`; `null` for an unknown slug (S5 maps that to 404).
- `listTrophies() → Trophy[]` — `listSection("certification")` narrowed so `metadata.category` (certification | award) and `status` (unlocked | in_progress | archived) are typed; S8's one-kind query.
- From `lib/content/schema.ts`: the enums and their types, `Entry`, `EntrySummary`, `EntryOf<K>`, `Link`, `Tag`, `Media`, `ENTRY_COLUMNS`, `TILE_COLUMNS`, `compareRecency`-compatible shapes. From `lib/db/client.ts`: `CONTENT_TAG`, `CONTENT_REVALIDATE_SECONDS`.

### Caching and revalidation
Every read is a GET through supabase-js whose fetch is wrapped by `withContentCache` in `lib/db/client.ts`, which adds `next: { revalidate: 3600, tags: ["content", "content:<table>"] }` and passes everything else through, resolving `globalThis.fetch` at call time (Next installs its patched fetch there at runtime). Inside Next this lands in the fetch Data Cache — durable on Vercel across requests and deploys, deduplicated within one render — so a distinct query costs one database round-trip per hour; explicit `next.revalidate` wins over Next's "requests with an `Authorization` header are not cached" heuristic (traced in `next/dist/server/lib/patch-fetch.js`, 16.3.2). A route that performs these reads while prerendering inherits `revalidate ≤ 3600` (ISR) unless it declares its own segment config or is dynamic — **S5/S6's decision**, deliberately not made here (no `cacheComponents`, no route config, no `next.config.ts` change; `'use cache'` is a compile error without `cacheComponents` in 16.3.2 and would have forced route-level choices). `revalidateContent()` marks everything stale (Next 16's recommended `"max"` profile — the next visitor gets the cached page while it refreshes); `expireContent()` expires it immediately for webhooks; admin Server Actions that must read their own writes use `updateTag(CONTENT_TAG)` from `next/cache`. Outside Next (Vitest, scripts) the `next` field is ignored and reads are live. The 3600 s TTL is an assumption (content changes are owner edits) — change `CONTENT_REVALIDATE_SECONDS` if you disagree.

### Decisions, one line each
- **Read path — supabase-js over PostgREST**, not `pg` in the app: it uses the public key and URL Vercel already holds, cannot escalate past `anon`, and needs no database secret in Vercel; the price is the sidecar for tests.
- **Generated types — yes, committed**: supabase-js's select typing is only as strong as its `Database` generic and hand-writing it re-transcribes the migration; Zod still owns the runtime shape and the closed value sets. Regenerate after any migration (`npm run db:types`); `api.test.ts` fails if the `entries` columns drift.
- **Facet counts in code** from one `select=facet` request: PostgREST `db-aggregates-enabled` defaults to false and hosted leaves it off.
- **Zod boundary throws**: an invalid row is an editing mistake to fix, not something to hide.
