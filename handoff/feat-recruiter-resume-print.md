- **The repo's first `@media print` rules, in two files.** The colour pin is in `app/app.css`; the layout is in `app/site.module.css`. Every declaration in both is a `var()`, a keyword, `0`, or `attr(href)` — 19 declarations, all checked by a test.
- **The pin exists because a print stylesheet inherits `prefers-color-scheme`.** Without it a dark-mode visitor prints `--color-text: #F2ECDD` — near-white — onto a sheet whose `--color-surface` the printer omits by default, and gets an effectively blank page. It restates six themed colours as the static ink tokens under three selectors mirroring `tokens.css`'s three theme blocks, which tie on specificity and win on source order (`app/layout.tsx` imports `tokens.css` before `app.css`). `--border-hairline`, `--border-strong` and `--elevation-*` are static composites referencing those tokens and custom-property substitution is lazy, so they inherit the pin without being restated.
- **The pin could not live in `tokens.css`.** `design/tokens/build.mjs:91-101` enumerates the four blocks that file may contain and fails on a fifth, so a `@media print` block there breaks `tokens:check`. That is recorded in `CLAUDE.md` as a convention, because it is the first thing the next person will try.
- **One new static token: `--color-ink-muted: #5A574B`.** The light `--color-text-muted` now reads `var(--color-ink-muted)`, so there is one source per colour rather than a duplicated hex the generator could not catch drifting. `tokens:check` **57 → 58 static tokens**, 19 themed unchanged, **68/68 contrast pairs pass**, and `CONTRAST.md` came back **byte-identical** — the resolved light value is unchanged, which is the point. `tokens.json` and `specimen.html` regenerated; `specimen.html` links `tokens.css`, so the new `var()` resolves from `:root` and the specimen still renders.
- **No `@page` rule, deliberately.** Custom properties do not resolve in the page context, so a tokenised `@page { margin }` is impossible and a hardcoded one is forbidden. The UA's own page margins are used, and `.main` drops its `max-width` and `padding` so the content fills them.
- **Print layout:** the skip link and site header are hidden; the ≥44 px minimums come off chips, tags and index/resume title links, because a touch target is a screen requirement and on paper only spends vertical space; `break-inside: avoid` on entry and resume rows, `break-after: avoid` on section headings; `background: none` on `.body code` / `.body pre` so a visitor who enables background graphics does not get filled boxes.

The scope matters: the contact block's link text is already the URL, and an unscoped rule would print each one twice. Verified both ways — `entryAfter` carries the real credential URL, `contactAfter` is `none`.

## Deviated from plan

- **The print proof was wrong twice before it was right, and both failures were silent.** Puppeteer's `emulateMediaType` and `emulateMediaFeatures` each issue their own `Emulation.setEmulatedMedia` and **wipe the other's argument**. Features-then-type produced three "different" states that were all system-dark; type-then-features produced `matchMedia("print") === false`, so the print block was never applied. Neither throws. Both are only visible if you assert the emulation itself, which is why the driver now reads back `matchMedia("(prefers-color-scheme: dark)")` and `matchMedia("print")` in every state and both are set in one raw CDP call. **Anyone reusing this technique on `feat/recruiter-seo` or `lane/console-shell` should assume the same trap.**
- **A counterfactual was added that the plan did not ask for**, because "the pin works" is not provable from the pinned state alone. The driver deletes just the palette-pinning `@media print` rule through the CSSOM and re-measures the same page. It is the measurement that shows the bug is real; without it, three identical states are equally consistent with the emulation being broken.
- **`--color-surface` is deliberately not pinned.** Printers omit backgrounds, and painting the sheet cream for anyone who enables background graphics is worse than not painting it, so `body { background: none }` under `@media print` states that instead. The measured print `background-color` is `rgba(0, 0, 0, 0)` in every state.
- **The unused semantic-state colours are not pinned either** — `--color-secondary`, `--color-on-secondary`, `--color-success`, `--color-warning`, `--color-error`, `--color-info`, `--color-on-state`. Nothing in `site.module.css` renders them today, and pinning tokens no page consumes would be inventing scope. **The consequence is real and is written down rather than hidden: the first page that renders one of them will print it in the dark-theme value.** Whoever adds that page adds the pin.
- **`--color-focus-ring` is not pinned.** Focus rings do not print.
- **`CLAUDE.md`'s S6 bullet said "no contact details anywhere in the tree" and is now false**, so it was rewritten rather than left standing — this is the branch that bullet named as the changer, which makes it a superseded claim rather than the "record, do not rewrite" case that applies to a prior handoff's facts.
